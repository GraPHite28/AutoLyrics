# AutoLyrics — план разработки

Десктопная программа для Windows 11: сама определяет, какой трек играет на ПК, находит синхронизированный текст (LRC), показывает его строка за строкой и рисует аудио-визуализатор, подобранный под жанр. Стиль — мягкий, цветастый, размытые градиенты в духе «Моей волны» из Яндекс Музыки. Все элементы интерфейса скрыты и появляются по ПКМ.

---

## 1. Что должна уметь программа (требования)

| # | Требование | Критерий готовности |
|---|-----------|---------------------|
| 1 | Автоматически подхватывать музыку на ПК | Запустил любой плеер (Яндекс Музыка, Spotify, браузер, VLC…) — программа за ≤2 с узнала артиста, название, длительность и позицию |
| 2 | Искать синхронизированный текст | Для популярных треков текст найден автоматически, строки подсвечиваются в такт, точность ±200 мс |
| 3 | Аудио-визуализатор под жанр | Визуализатор реагирует на реальный звук системы; стиль меняется в зависимости от жанра трека |
| 4 | Мягкий цветастый стиль | Размытый градиентный фон из цветов обложки, крупный округлый шрифт, «стеклянные» полупрозрачные кнопки |
| 5 | UI скрыт по умолчанию | На экране только фон + текст + визуализатор. ПКМ в любом месте открывает меню; через несколько секунд бездействия меню плавно исчезает |

---

## 2. Выбор технологий

**Рекомендуемый стек: Tauri 2 (Rust) + TypeScript + WebGL.**

- **Rust-бэкенд** — доступ к нативному Windows API: определение трека, захват системного звука, FFT.
- **Веб-фронтенд (TS + WebGL/Canvas)** — мягкие размытые градиенты, плавные анимации и шейдеры делаются в вебе заметно проще и красивее, чем в WPF/Qt.
- Маленький размер (~10 МБ против ~150 МБ у Electron), низкое потребление ресурсов — важно для программы, которая работает фоном.

Альтернативы (если Rust не подходит): Electron + C#-сайдкар; WPF + SkiaSharp. По возможностям одинаково, но тяжелее или менее красиво.

### Ключевые библиотеки

| Задача | Решение |
|--------|---------|
| Текущий трек, позиция, состояние плеера | Windows **SMTC** (`GlobalSystemMediaTransportControlsSessionManager`) через крейт `windows` |
| Захват звука, который играет на ПК | **WASAPI loopback** через крейт `cpal` (или `wasapi`) |
| Спектр, бит, громкость | `rustfft` + собственный анализ (энергия по полосам, spectral flux, BPM) |
| HTTP-запросы | `reqwest` |
| Кэш | SQLite (`rusqlite`) — тексты, жанры, цвета обложек |
| Цвета из обложки | `colorthief`-подобный алгоритм (k-means) на фронте или `image` + `kmeans_colors` в Rust |
| Окно без рамки, трей, автозапуск | Tauri-плагины `window`, `tray-icon`, `autostart` |

## 3. Архитектура

```
┌──────────────────────── Rust (Tauri backend) ────────────────────────┐
│  media_watcher   — SMTC: трек, позиция, пауза/плей, обложка          │
│  audio_capture   — WASAPI loopback → буфер PCM                       │
│  analyzer        — FFT, полосы, бит, BPM, «энергия» (60 раз/с)       │
│  lyrics_service  — поиск LRC по провайдерам + кэш                    │
│  genre_service   — определение жанра (теги → эвристика по звуку)     │
│  store           — SQLite + настройки (JSON)                         │
└───────────────┬───────────────────────────────────────┬──────────────┘
          события Tauri (track, lyrics, genre)    поток спектра (~60 fps)
┌───────────────▼───────────────────────────────────────▼──────────────┐
│  Frontend (TypeScript)                                               │
│  Background (WebGL blobs) · Visualizer · LyricsView · ContextMenu    │
└──────────────────────────────────────────────────────────────────────┘
```

Поток данных: SMTC сообщает «сменился трек» → `lyrics_service` и `genre_service` параллельно ищут текст и жанр → фронтенд получает события → меняет фон (цвета обложки), визуализатор (под жанр) и список строк. Позиция воспроизведения идёт от SMTC, между опросами интерполируется локальными часами.

## 4. Определение музыки на ПК

1. Подписаться на SMTC: события `CurrentSessionChanged`, `MediaPropertiesChanged`, `PlaybackInfoChanged`, `TimelinePropertiesChanged`.
2. Брать: `title`, `artist`, `album`, `thumbnail` (обложка), `position`, `duration`, `playbackStatus`.
3. Если активных сессий несколько — выбирать ту, что в статусе `Playing`; в настройках можно закрепить приложение-источник.
4. Нормализация названия: убрать `(feat. …)`, `- Remastered`, `[Official Video]`, ` - Topic` и т. п. (оригинал сохранить для кэша).
5. Позиция: SMTC обновляет её редко → хранить `(position, timestamp)` и считать `position + (now − timestamp) × rate`; корректировать при каждом событии. Перемотку определять по скачку.
6. **Запасной вариант**, если плеер не отдаёт метаданные в SMTC: распознавание по звуку (AcoustID / ACRCloud) на захваченном loopback-аудио — отдельный этап в конце, опционально.

## 5. Поиск синхронизированного текста

**Цепочка провайдеров (по очереди, до первого успешного):**

1. **LRCLIB** (`lrclib.net`) — бесплатный, без ключа, отдаёт `syncedLyrics` в формате LRC. Запрос `/api/get` по `track_name + artist_name + album_name + duration`, затем `/api/search`.
2. **NetEase Music** (неофициальный API) — хорошее покрытие, в том числе азиатской и части русской музыки.
3. **Musixmatch / Megalobiz** — как дополнительные запасные.
4. Если есть только несинхронизированный текст — показать статично с мягкой прокруткой по времени трека (оценка по длительности).
5. Нет текста вообще → показать название и артиста + визуализатор («инструментал / текст не найден»).

**Правила выбора кандидата:** совпадение артиста и названия после нормализации (нечёткое, Левенштейн), длительность отличается ≤ 2–3 с; из нескольких кандидатов — ближайший по длительности.

**Отображение:**
- Парсер LRC: `[mm:ss.xx]` → массив `{time, text}`, поддержка нескольких меток на строку и тега `[offset:]`.
- Текущая строка крупная и яркая, соседние — мелкие и полупрозрачные, плавный скролл, лёгкое размытие дальних строк.
- Ручная подстройка сдвига (−/+ 100 мс) из меню, сдвиг запоминается для трека.
- Кэш в SQLite: повторное прослушивание работает без интернета.

## 6. Аудио-визуализатор «под жанр»

### 6.1 Захват и анализ звука
- WASAPI loopback с устройства вывода по умолчанию (работает с любым плеером, смена устройства отслеживается).
- Окно FFT 2048, перекрытие 50%, сглаживание (экспоненциальное затухание) — чтобы выглядело «мягко».
- Выход анализатора: 64 лог-полосы, `bass / mid / treble`, общая громкость, детектор удара (spectral flux + порог), оценка BPM.

### 6.2 Определение жанра (по убыванию надёжности)
1. **Теги из онлайн-источников** по артисту/треку: iTunes Search API (`primaryGenreName`, без ключа), Deezer API (жанр альбома, без ключа), MusicBrainz / Last.fm (теги; Last.fm нужен бесплатный ключ).
2. **Эвристика по звуку** (если теги не найдены или нет сети): BPM, spectral centroid, доля баса, динамический диапазон, «ударность» → грубые классы (энергичный / спокойный / тяжёлый / акустический).
3. Ручной выбор стиля визуализатора в меню (переопределяет авто).

Жанры сводятся к 6–7 группам:

| Группа | Жанры | Визуализатор |
|--------|-------|--------------|
| Electronic / Dance | house, techno, EDM, trance | Яркие вертикальные «капсулы»-полосы, пульсация фона на каждый бит |
| Hip-Hop / R&B | rap, trap, r&b | Крупный «дышащий» блоб, реагирующий на бас, плавные волны |
| Rock / Metal | rock, punk, metal | Радиальные острые лучи, резкие вспышки, контрастные цвета |
| Pop / K-Pop | pop, k-pop, dance-pop | Разноцветные мягкие блобы + частицы, живые пастельные переходы |
| Chill / Lo-fi / Ambient | lo-fi, ambient, chillout | Медленные «северное сияние»-волны, минимум резких движений |
| Classical / Jazz / Acoustic | classical, jazz, folk | Тонкие плавные линии-волны, нежное свечение |
| Default | всё остальное | Мягкие колеблющиеся блобы (как «Моя волна») |

Переход между стилями — кросс-фейд 1–2 с, без «прыжков».

### 6.3 Техника рендера
- Один WebGL-холст на весь экран: фон (шейдер из 4–5 размытых метаболлов цветов обложки, как на скриншоте) + слой визуализатора поверх.
- Цвета берутся из обложки (доминантные 3–5 цветов, подправленные по насыщенности/яркости, чтобы всегда было «сочно, но мягко»); без обложки — палитра по жанру.
- Цель: 60 fps, <5% CPU / умеренная нагрузка GPU; при сворачивании/потере фокуса — снижение до 30 fps, при паузе музыки — «спящая» медленная анимация.

## 7. Интерфейс и стиль

### 7.1 Состояние по умолчанию
Видны **только**: размытый цветной фон, визуализатор, строки текста. Ни кнопок, ни заголовка окна, ни курсора-подсказок.

### 7.2 Контекстное меню по ПКМ
- Правый клик в любой точке окна → меню появляется **рядом с курсором** (округлые «стеклянные» пилюли, как кнопка «Настроить» и «Для вас / Тренды» на референсе), плавная анимация (scale + fade, ~200 мс).
- Закрывается: клик вне меню, `Esc`, или автоскрытие через ~5 с бездействия.
- Левая кнопка мыши по пустому месту — перетаскивание окна; двойной клик — полноэкранный режим.

### 7.3 Пункты меню
1. Карточка трека (обложка, название, артист — мини-плашка как «Для вас»).
2. Текст: размер шрифта, сдвиг синхронизации (−/+), выбор провайдера, «искать заново».
3. Визуализатор: Авто / конкретный стиль / интенсивность / выкл.
4. Фон: сила размытия, насыщенность, цвета из обложки или свои.
5. Окно: поверх всех окон, прозрачный фон/«клик насквозь», полноэкранный, режим «плавающая панель с текстом».
6. Источник звука/плеера, автозапуск, язык, сворачивание в трей.
7. Выход.

### 7.4 Визуальный язык
- Шрифт: округлый гротеск (Manrope / Nunito / Onest — кириллица обязательна), жирное начертание для текущей строки.
- Углы скруглены максимально, тени мягкие, фон кнопок — полупрозрачный белый с `backdrop-filter: blur`.
- Анимации — на пружинах/ease-out, ничего резкого, кроме режима Rock.
- Тёмная база (как на референсе) + цветные пятна; контраст текста проверяется автоматически (подложка/тень, если фон светлый).

| 5. Звук | ✅ `analyzer.rs`: FFT, 48 полос, бит, темп; событие `spectrum` 40 раз/с |
| 6. Жанры | ✅ 7 стилей визуализатора, жанр от Shazam / iTunes, а если неизвестен — оценка по звуку; стиль можно выбрать вручную |

**Добавлено после теста (Яндекс Браузер не сообщает трек системе):** распознавание по звуку.
- `audio_capture.rs` — WASAPI loopback (всё, что играет на ПК), кольцевой буфер 24 с.
- `recognizer.rs` — отпечаток Shazam (крейт `songrec-lib`, GPL-3) → название, артист, обложка и смещение в треке, по которому идут собственные часы для синхронизации текста. Перепроверка раз в 25 с ловит смену трека и перемотку; тишина = пауза.
- SMTC остаётся главным: если плеер сам сообщает трек, распознавание молчит.
- В меню: «Найденные варианты» (выбор другой песни), «Определить сейчас», переключатель «По звуку».
- Заставка трека (src/ui/splash.js): поиск (сонар) → обложка вырастает из центра, справа выезжают название и артисты → при найденном тексте заставка уезжает вверх и остаётся приглушённой. Каждый этап отключается в меню (`Анимации`).
- Конец трека: источник текста сообщает длительность, по ней распознаватель понимает, что трек доиграл, забывает его и определяет следующий (важно для переходов без паузы).
- Риск: сервис Shazam используется неофициально и может измениться/ограничить запросы.

- Языки (7: ru, en, de, fr, pl, zh, ja): `src/i18n`. Первый запуск (`ui/onboarding.js`): приветствие по кругу на всех языках просит включить любимую песню на родном языке, язык определяется по найденному тексту (`i18n/detect.js`); внизу кнопка ручного выбора. Язык меняется в меню.
- Визуализатор при поиске трека сглажен и размыт, как фон.
- Liquid Glass у кнопок (`ui/glass.js`: SVG-карта смещения + `backdrop-filter`, только Chromium/WebView2), переключается в меню.

Отступления от плана: фронтенд написан на **чистом JavaScript (ES-модули) без сборщика** — на этой машине нет Node.js, а для текущих задач он не нужен (`withGlobalTauri`). Шрифт — системный Segoe UI Variable (свои шрифты можно подложить позже). Кэш текстов — JSON-файлы в папке кэша приложения.

## 10. Риски и решения

| Риск | Что делаем |
|------|-----------|
| Плеер не отдаёт позицию трека в SMTC | Считаем по локальным часам от момента смены трека; ручной сдвиг; сброс при паузе |
| Для трека нет синхронизированного текста | Цепочка провайдеров → статичный текст → режим «только визуализатор» |
| Неверная версия текста (live/remix) | Сверка длительности, при расхождении — «искать другой вариант» в меню |
| Нет ключа/нет сети для жанра | Эвристика по звуку, стиль «Default» |
| Нагрузка на GPU/CPU | Адаптивный FPS, упрощённые шейдеры, пауза рендера при простое |
| Неофициальные API (NetEase и др.) могут измениться | Провайдеры за общим интерфейсом, легко заменяются; кэш снижает зависимость |
| Тексты защищены авторским правом | Показываем только локально, для личного использования, без сохранения/распространения сверх кэша; ссылаемся на источник (LRCLIB) в «О программе» |
| WASAPI loopback и защищённый контент | Часть DRM-сервисов может отдавать тишину — тогда визуализатор переходит в «idle»-анимацию |
